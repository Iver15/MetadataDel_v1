# MetadataDel: план реализации окна и установки

> **Для исполнителя:** выполнять по задачам с навыком `superpowers:executing-plans`. Шаги отмечать через `- [ ]`. Планирование не означает, что код уже реализован или проверен.

**Цель:** добавить окно обработки файлов и удобные установщики, сохранив удаление метаданных правым кликом главным и независимым сценарием.

**Архитектура:** существующие WinForms и AppKit, общее ядро очистки. Windows GUI вызывает Core; macOS GUI — вложенный CLI с отдельным структурированным ответом. Существующие shell/Finder-вызовы сохраняют маршрутизацию и поведение.

**Технологии:** C#/.NET 8, WinForms, Objective-C/AppKit, Bash, Inno Setup, WiX 5, GitHub Actions.

**Спецификация:** [2026-10-08-desktop-installation-design.md](../specs/2026-10-08-desktop-installation-design.md).

## Общие ограничения

- Удаление метаданных правым кликом остаётся главным сценарием, без нового GUI и дополнительных подтверждений.
- Windows shell: `--log`; Finder: `--log --backup=on`; GUI: резервные копии включены по умолчанию и не меняют эти команды.
- Форматы PDF/DOCX/XLSX/DOC/XLS; существующая обработка папок сохраняется; новый GUI первой версии принимает только файлы.
- Коды старой очистки 0/1/2 и алгоритмы очистителей не меняются.
- .NET 8, self-contained дистрибутивы, macOS 12+, отдельные macOS arm64/x64 сборки. Новые GUI-фреймворки не добавляются.
- Не вводить постоянную историю документов, автообновление, фонового агента и новые форматы.
- Работать в отдельной ветке `codex/desktop-installation` после проверки ownership и состояния checkout; чужие изменения не включать.

## Приоритетные риски проверки

1. Shell-аргументы ошибочно открывают новое окно или меняют режим backup — задача 1 и приёмка 6.
2. Кириллица, пробелы, кавычки, имя с `-`, повтор пути или ссылка приводят к неверной обработке — задачи 2–4.
3. Ошибка одного документа, заполненный диск или невозможность создать `.bak` скрываются за общим успехом — задача 2 и приёмка 6.
4. Обновление/извлечение DMG/перезапуск GUI ломают Finder либо создают вторую Windows-установку — задачи 3, 5 и 6.
5. Закрытие окна, повторный запуск очереди, сбой дочернего процесса дают ложный успех или повторную запись — задачи 3, 4 и 6.

## Задача 2. Тонкий адаптер очистки для GUI

**Интерфейсы:** `SingleFileCleaningService.CleanAsync(string path, CleanOptions options, CancellationToken ct = default) -> Task<CleanResult>`; `GuiCleanCommand.RunAsync(string[] args, TextWriter output, TextWriter error) -> Task<int>`.

**Машинный вызов:** `--gui-clean --backup=on|off -- <один абсолютный путь>`. Только macOS CLI принимает этот режим в первой версии. Ноль/несколько путей, неизвестные параметры или сочетание со служебными режимами отклоняются до записи файлов, код 2.

**JSON v1:** один UTF-8 объект в stdout: `schemaVersion: 1`, `inputPath: string`, `outputPath: string|null`, `success: bool`, `message: string|null`. Успех — код 0, ошибка — 2. Непустое сообщение при success=true отображается как предупреждение. На ошибке outputPath=null. stdout не содержит текстовых логов; диагностические сообщения идут в stderr. Протокол не добавляет новых постоянных журналов с путями.

- [ ] Добавить падающие тесты сервиса: успешный DOCX и резервная копия; повреждённый DOCX сохраняет исходные байты; неизвестное расширение/символическая ссылка отклоняются; повторная копия не перезаписывает первую. Использовать существующие генераторы документов в тестах.
- [ ] Реализовать адаптер через `CleanerFactory` и существующие `IFileCleaner`, с явным отказом для папок и ссылок. Не переписывать транзакции и очистители. Реальные исключения преобразовать в неуспешный `CleanResult`, сохраняя понятную причину.
- [ ] Добавить тесты JSON-команды: корректная сериализация кириллицы/кавычек; ошибочная опция и два пути не меняют документы; warning и альтернативный выходной путь сохраняются; неуспех не содержит фиктивного выходного пути. Для warning/fallback использовать управляемую подмену очистителя через внутренний тестовый конструктор сервиса `SingleFileCleaningService(IServiceProvider services)`.
- [ ] Реализовать отдельную ветку macOS CLI; проверить `--gui-clean --backup=on -- <fixture>` через настоящий subprocess, JSON parse и коды выхода. Обычная очистка, audit, помощь и Finder остаются прежними.
- [ ] Запустить `dotnet test MetadataDel.Core.Tests -c Release`, `dotnet build MetaDataDel.sln -c Release`, `python3 scripts/tests/smoke.py <dotnet>`. Требование: все проверки проходят, старые smoke-сценарии сохранены.

## Порядок и завершение

Предпосылка macOS-сборки: 2026-10-08 запуск системного `/usr/bin/python3` в этой среде завершился требованием принять лицензию Xcode. До задач сборки проверить `xcodebuild -checkFirstLaunchStatus` и рабочий Python; принятие лицензии оставляется пользователю. Эта проблема не мешает подготовке Markdown-плана, но сборку здесь пока нельзя считать готовой к запуску.

Выполнять 1 → 2 → 3 → 4 → 5 → 6. После каждого этапа — проверка diff и соответствующие тесты; коммиты только относящихся к задаче файлов. Публичная публикация артефактов — отдельное действие после приёмки. План исполняется в рабочей ветке; выполненные проверки и оставшиеся пункты перечислены в docs/DESKTOP-ACCEPTANCE.md.

Самопроверка плана: основной сценарий и backup закреплены задачами 1/6; UI — 3/4; миграция и установка — 3/5; подписи и живые проверки — 6. Пять рисков выше имеют владельцев и проверки. Автоматизация не подменяет доказательство работы системного контекстного меню.
