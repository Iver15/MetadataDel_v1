# MetadataDel: окно обработки и установка

Дата: 2026-10-08. Статус: реализовано в рабочей ветке; границы приёмки — в docs/DESKTOP-ACCEPTANCE.md.

## Цель и обязательное условие

Добавить небольшой удобный интерфейс обработки файлов и понятную установку Windows/macOS. **Удаление метаданных правым кликом остаётся главным сценарием.** Новое окно дополняет его и не становится обязательным промежуточным шагом.

## Поведение, которое сохраняем

- Windows: «Удалить метаданные» в контекстном меню и «Отправить» сразу запускают обработку; GUI не открывается. Существующее расположение команды в меню Windows 11 сохраняется, новая shell extension не входит в работу.
- macOS: Finder → «Быстрые действия» → «Удалить метаданные (MetadataDel)» сразу запускает обработку. Открытое окно MetadataDel для этого не требуется.
- Имена существующих пунктов меню, форматы PDF/DOCX/XLSX/DOC/XLS, обработка папок существующими маршрутами и параметры CLI сохраняются.
- Настройки резервного копирования не объединяются: Windows shell сейчас вызывает `--log`, Finder — `--log --backup=on`. Новое окно по умолчанию создаёт копии; его переключатель не меняет поведение правого клика.
- Сохраняются коды выхода очистки 0/1/2, предупреждения, транзакционная запись, отказ от обработки символических ссылок и уникальные имена повторных резервных копий.
- Поддержка .NET 8, self-contained дистрибутивы, macOS 12+, отдельные macOS arm64/x64 сборки. Новые GUI-фреймворки не добавляются.

## Новое окно

Один экран: логотип и название, большая зона перетаскивания, «Выбрать файлы», список файлов, флажок «Создавать резервные копии», кнопка «Очистить N файлов». Под флажком: «Исходные файлы будут заменены после очистки».

Перетаскивание и выбор только добавляют файлы. Обработка начинается кнопкой. Поддерживаются несколько файлов; папки в новом окне пока отклоняются с подсказкой использовать существующее контекстное меню. Это ограничение GUI не меняет поддержку папок через CLI/Finder/имеющиеся пункты Проводника.

Статусы: «Готов к очистке», «Обрабатывается», «Очищен», «Очищен с предупреждениями», «Не обработан». Отображаются число завершённых файлов, причина ошибки/предупреждение и фактический путь результата. «Показать в папке» открывает расположение результата, включая отдельную очищенную копию PDF.

Во время обработки очередь и настройки блокируются; повторное нажатие не запускает второй пакет. Штатное закрытие окна откладывается до завершения текущего пакета. Обработка последовательная в фоне, интерфейс остаётся отзывчивым. Одинаковые нормализованные пути добавляются один раз; после завершения успешные строки не обрабатываются повторно без удаления и повторного добавления.

Настройки содержат состояние интеграции, её установку/восстановление и справку. Удаление Windows-приложения делегируется установившему его механизму. Постоянная история документов, tray/menu-bar агент, автообновление, просмотр метаданных и новые форматы не входят в эту версию.

## Windows

Сохраняем WinForms и Inno Setup. Запуск без аргументов открывает новое главное окно. Все существующие вызовы с аргументами продолжают работать без этого окна. Установщик создаёт ярлыки, предлагает запуск приложения, сохраняет выбор интеграции при обновлении. MSI остаётся отдельным корпоративным способом установки, получает ярлык в меню «Пуск».

GUI не вызывает самоустановку поверх Inno/MSI и не удаляет файлы, принадлежащие этим установщикам. В настройках переход к системному управлению приложениями; старые CLI-команды установки сохраняются для совместимости с portable-сценарием.

## macOS

DMG содержит `MetadataDel.app` и ссылку на «Программы». Пользователь копирует приложение в `/Applications` или `~/Applications` и запускает его. Окно строится на существующем AppKit/Objective-C. Обработчик .NET находится внутри bundle.

При первом запуске приложение заметно предлагает «Включить очистку правым кликом в Finder». Оно устанавливает существующие CLI-команды и workflow в профиль пользователя, без `sudo`. При обновлении ранее включённая интеграция сохраняется и обновляется автоматически; при сбое показывается «Восстановить», без ложного сообщения об успехе. Для CLI сохраняем стабильный путь `~/.local/bin/metadatadel` и `mdel`, чтобы действие Finder не зависело от запущенного GUI или смонтированного DMG.

Из DMG можно открыть окно, но включение/обновление интеграции требует сначала скопировать приложение в постоянную папку. Приложение не сохраняет путь на съёмный том. Обновление CLI — через временный соседний файл и атомарную замену; неудача не уничтожает работавшую версию. Состояние установки включает версию CLI, а не только наличие файлов.

В настройках есть явное удаление компонентов Finder/CLI; затем пользователь перемещает приложение в Корзину. Документы и их `.bak` не удаляются. Политика удаления журналов остаётся текущей; исправляем противоречащую ей документацию.

## Обмен с обработчиком

Windows вызывает существующие очистители Core через маленький сервис обработки одного файла. macOS запускает вложенный CLI через `NSTask` с массивом аргументов, без shell. Для нового GUI добавляется отдельный машинный режим ответа JSON для одного файла; существующий текстовый CLI и Finder его не используют. Ответ содержит исходный и фактический выходной путь, успех и сообщение, чтобы не разбирать русскоязычные логи и не терять предупреждения.

## Приёмка и распространение

Правый клик проверяется до и после обновления с 2.3.0, при закрытом GUI, после извлечения DMG, для пяти форматов и имеющихся сценариев нескольких файлов/папок. Проверка установки включает чистый профиль, обновление, повторную установку и удаление.

Подпись Windows и Developer ID/notarization macOS — отдельный этап публичного выпуска. Наличие сертификатов и доступов нужно проверить при реализации; в исследовании они не проверялись. Нельзя обещать отсутствие SmartScreen-предупреждений только на основании подписи. Локальная сборка и CI не заменяют интерактивную приёмку на Windows и macOS.

Основания: текущие `SetupLauncher.cs`, `Program.cs`, `MetadataDelInstaller.m`, скрипты Finder, Inno/WiX и исследование в чате. Требования подписи: [Apple](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution), [.NET для macOS](https://learn.microsoft.com/en-us/dotnet/core/deploying/macos), [SmartScreen](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/smartscreen-reputation).
